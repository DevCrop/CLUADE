# Global Claude Code Architecture

This document describes the architecture of this machine's global Claude Code setup. Read this before changing rules, hooks, or directory layout. Companion documents:

- `HARNESS_ARCHITECTURE.md` — harness design pattern (3-Layer + Verification Loop, Anthropic-native), project-agnostic
- `CLAUDE.md` — operating rules (DO / DON'T)
- `RTK.md` — token-optimized CLI proxy reference
- `AUTOMATION.md` — session automation hooks (architecture diagram + auto-generated tables)
- `templates/order-match-checklist.md` — task self-verification template

## 1. Operating Environment

| Property | Value |
|---|---|
| OS | Windows 10 (native, no WSL) |
| Shell | Git Bash (primary) / PowerShell 5.1 |
| AI assistant | Claude Code (primary) + OpenAI Codex CLI (secondary — parallel / second-opinion work). See §10. |
| IDE host | VS Code with Claude Code extension |
| Drive layout | C drive (under `%USERPROFILE%`) for the `.claude` config root. Project work lives on D:; only the Claude infra itself is single-drive. |

**Rationale (single-drive on C)**: cognitive simplicity, tool universality (every Windows tool assumes `%USERPROFILE%\.claude`), and vanilla compliance with Claude Code's default. C has 88+ GB free; the entire setup is ~165 MB.

├── sessions/                              # session state (ephemeral)
├── session-env/                           # SessionStart artifacts (memory-lint.txt, compact-warning.txt)

**Anti-pattern**: do not create NTFS junctions to redirect any subdirectory to another volume. The previous D-split design was reverted because it complicated backup tooling, broke drive-letter assumptions in third-party scripts, and provided no measurable benefit at this data scale.

## 3. Path Resolution Convention

Every script and document references the config root via:

```powershell
$ClaudeRoot = if ($env:CLAUDE_CONFIG_DIR) {
    $env:CLAUDE_CONFIG_DIR
} else {
    Join-Path $env:USERPROFILE '.claude'
}
```

`CLAUDE_CONFIG_DIR` is **not set** in any registry scope — the env var fallback exists only to honor user overrides if a future need arises. The default code path always resolves to `%USERPROFILE%\.claude`.

In documentation: use `%USERPROFILE%\.claude\` (Windows-native, expands in cmd / PowerShell / Git Bash) or `~/.claude/` for compactness.

**Forbidden**: relocating the `.claude` config root to a non-profile drive (`D:\.claude\`, `D:\.claude-data\`). D-drive paths in project content are fine — the rule targets the infra root, not the project.

## 4. Hook Architecture

Eight hook events are registered in `settings.json` (plus a `statusLine` renderer). SessionEnd registers two command entries, so total command count is nine. See `AUTOMATION.md` for the full sequence diagram and the auto-generated registration table.

| Event | Purpose | Async |
|---|---|---|
| PreToolUse (Bash) | RTK auto-rewrite via `rtk hook claude` (native binary, v0.37.2); raw output bypass: `rtk proxy <cmd>` | no |
| SessionStart | regenerate AUTO-marks, auto-pin, memory-lint, weekly memory-backup, 24h doc gate, 60d plan archive, **D-remnant detection → oneshot consolidation** | no |
| SessionEnd | retention rotations (13 categories), MEMORY.md link integrity, kill stale workers, drift queue drain | yes |
| PostToolUse (Edit\|Write\|Bash) | enqueue edited files / dep-install audits to `.drift-queue` | yes |
| UserPromptSubmit | inject git status + recent commits when repo is dirty (skip-when-clean keeps prompt cache warm) | no |
| PreCompact | hard-link snapshot of MUST-preserve set into `backups/precompact-<ts>-<sid>` | no |
| PostCompact | verify `@import` chains + active plan readability; write `compact-warning.txt` on issues | yes |
| Stop | append rtk session stats to `reports/token-usage.md` | yes |
| statusLine | render status line (includes `compact:warn` indicator if PostCompact flagged a loss) | (poll) |

**Design principle**: each hook runs in <100 ms in the synchronous path. Heavier work (`check-updates-worker`) is spawned detached via `Start-Process -WindowStyle Hidden`. Detached workers survive parent exit; PowerShell jobs do not.

## 7. RTK Strategy (Token Optimization)

RTK is a Rust-based CLI output filter (60–90% token savings). On this machine:

- **Mode**: PreToolUse hook (`rtk hook claude` — native binary, v0.37.2) auto-prefixes every Bash call. Raw output without filtering: `rtk proxy <cmd>`. Permanent exclusion: `~/.config/rtk/config.toml → exclude_commands`.
- **Coverage**: noisy multi-line outputs (`git`, `docker`, `tsc`, test runners, `find`, log files, `gh pr`, package managers).
- **Skip**: built-ins (`echo`, `pwd`), already-prefixed commands, and bypassed calls — pass through unchanged.

Detailed savings table: see `RTK.md`.

## 8. Order Match Verification

Every non-trivial task ends with a self-verification step before the AI declares completion. Procedure (full template at `templates/order-match-checklist.md`):

1. Restate the user's order verbatim.
2. List acceptance criteria (observable state).
3. Map each criterion to evidence (`file:line`, command output, test result).
4. Detect scope creep — anything done outside the order? Justify or revert.
5. Honor constraints — language (Korean chat / English AI artifacts), paths (no `D:\.claude`), tools, banned actions.

If any criterion lacks evidence: do **not** declare done. Either complete the gap or report it explicitly.

This rule is the system's primary safeguard against the "AI says done but didn't actually finish" failure mode.

## 9. Vanilla Compliance + FOMO Guard

Two principles that govern every change to this setup:

### Vanilla compliance

The closer to stock Claude Code behavior, the easier upgrades and debugging become. Do **not** customize unless an incident or measurable cost forced it. Document the trigger when adding any non-default rule.

Current non-vanilla customizations and their justifications:

| Customization | Trigger |
|---|---|
| `permissions.defaultMode = "bypassPermissions"` | productivity in trusted host environment |
| 8 hook events (9 command entries — SessionEnd registers 2) in `settings.json` | RTK auto-rewrite, upstream doc drift, plan rotation, prompt cache invalidation |
| `ENABLE_PROMPT_CACHING_1H` env | 1h prompt cache TTL for token efficiency |
| `effortLevel = "xhigh"` | model output quality preference |
| `model = "sonnet"` + `advisorModel = "opus"` | default working model = Sonnet; escalate to Opus via the `advisor` tool or `/model opus` for genuinely hard tasks |
| 13-category retention in `cleanup.ps1` | unbounded growth in volatile dirs |

### FOMO guard

A feature looking interesting is not justification. Before adding a hook / script / rule / skill / plugin, point to:

- a past incident the change prevents, OR
- a measurable benefit (token savings, time savings, error reduction)

If neither exists: skip it.

## 10. AI Tool Roles

Two AI assistants, one shared cross-AI rule set.

| Tool | Role | Config root |
|---|---|---|
| Claude Code | Primary assistant | `%USERPROFILE%\.claude\` |
| OpenAI Codex CLI | Secondary — parallel work, second opinions | `%USERPROFILE%\.codex\` |

The cross-AI rules (language convention, RTK prefixing, Order Match Verification, forbidden actions, Karpathy coding principles) are mirrored on both sides. Claude-specific behavior lives in `.claude\CLAUDE.md`; Codex-specific behavior in `.codex\AGENTS.md`, which carries the shared rules in Codex vocabulary and back-references `CLAUDE.md`.

**Two-tool cap.** Claude (primary) + Codex (secondary) is the limit — do not add a third AI surface. Rationale: more AI surfaces produce conflicting context, duplicate token costs, and inconsistent rule application; two tools with one synchronized rule set is the most surface this setup will carry.

## 11. Language Convention

| Audience | Language |
|---|---|
| User-facing chat replies | Korean |
| AI-consumed artifacts (docs, hooks, plans, memory, comments, log lines) | **English** |
| Code identifiers, paths, commands, error messages | English (verbatim, regardless of context) |
| Quoted user phrases (e.g. "done") | preserved as-is |

Rationale: AI consumption efficiency. English keeps tokens predictable across models and avoids encoding ambiguity (PowerShell 5.1 ANSI codepage corrupts em-dash and similar non-ASCII glyphs).
